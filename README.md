# hangeul-keymap-setup

macOS에서 **원하는 키를 한/영 전환 전용 키로** 쓰기 위한 셸 스크립트입니다.
지정한 키를 F18로 리매핑한 뒤, 그 F18을 입력 소스 전환 단축키로 지정하는
방식입니다. 고를 수 있는 키는 오른쪽 커맨드(⌘, 기본값) / 오른쪽 Alt / 한/영
전용 키 세 가지이며, 여러 개를 동시에 지정할 수도 있습니다.

Karabiner-Elements 같은 별도 앱이나 커널 확장 없이, macOS에 기본 내장된
`hidutil`과 `launchd`만 사용합니다.

## 요구 사항

- macOS 10.12 (Sierra) 이상
- Apple Silicon / Intel 모두 동작
- 관리자(sudo) 권한

## 어떤 키를 전환 키로 쓸지 고르기

| 옵션 | 대상 키 |
|---|---|
| `--right-cmd` | 오른쪽 커맨드(⌘) — 옵션을 안 주면 기본값 |
| `--right-alt` | 오른쪽 Alt(Option) |
| `--hangul-key` | 한/영 전용 키 (HID LANG1) |

여러 개를 동시에 지정할 수 있고, 지정한 키는 모두 F18을 보냅니다. 여러 키를
지정했더라도 시스템 설정에는 그중 아무 키나 하나만 등록하면 됩니다(아래
[설치 후 설정](#설치-후-설정-필수) 참고).

내 키보드에는 어떤 옵션이 맞는지 아래 표를 참고하세요.

| 키보드 | 권장 옵션 |
|---|---|
| 애플 키보드 / 맥용 배열 | 옵션 없이 기본값 (오른쪽 커맨드) |
| 윈도우용 풀사이즈 104키 | 기본값 그대로. 스페이스 오른쪽의 오른쪽 Win 키가 오른쪽 커맨드와 같은 HID 코드(`0x7000000E7`)를 보냅니다 |
| 오른쪽 Win 키가 없는 배열 (텐키리스 일부, 노트북 등) | `--right-alt` |
| 한글 배열 (한/영 키가 따로 있음) | `--right-alt --hangul-key` 둘 다 |
| 어느 쪽인지 모르겠음 | 세 개 다 지정해도 무방합니다 |

한글 배열 키보드의 한/영 키는 모델에 따라 LANG1을 보내기도 하고 101키 호환
모드에서 오른쪽 Alt로 인식되기도 합니다. 어느 쪽인지 모르겠다면 둘 다
걸어두면 됩니다.

## 설치

```sh
chmod +x hangeul-keymap-setup.sh

# 1) 모든 키보드, 오른쪽 커맨드 (가장 흔한 경우)
sudo ./hangeul-keymap-setup.sh install

# 2) 특정 키보드 한 대에만
sudo ./hangeul-keymap-setup.sh install --device

# 3) 윈도우용/한글 배열 키보드 한 대에 여러 키 지정
sudo ./hangeul-keymap-setup.sh install --device --right-alt --hangul-key
```

`--device`를 쓰면 연결된 HID 장치 목록이 출력되고, 적용할 키보드의
VendorID / ProductID를 입력받습니다. 내장 키보드는 그대로 두고 외장
키보드에만 적용하고 싶을 때 유용합니다. 대화식으로 입력을 받으므로
`curl | sudo sh` 처럼 파이프로 바로 실행하면 동작하지 않습니다.

연결된 장치 목록만 먼저 보려면 `./hangeul-keymap-setup.sh list` (sudo
불필요).

## 명령 / 옵션 레퍼런스

| 명령 | 설명 | sudo |
|---|---|---|
| `install` | 키 리매핑을 설치하고 즉시 적용 | 필요 |
| `uninstall` | 리매핑을 제거 | 필요 |
| `list` | 연결된 HID 장치 목록만 확인 | 불필요 |

`install`에 붙일 수 있는 옵션:

| 옵션 | 설명 |
|---|---|
| `--device` | 특정 키보드 한 대에만 적용 (목록에서 선택) |
| `--right-cmd` | 오른쪽 커맨드(⌘) 키를 사용 |
| `--right-alt` | 오른쪽 Alt(Option) 키를 사용 |
| `--hangul-key` | 한/영 전용 키(LANG1)를 사용 |

키 옵션은 여러 개를 동시에 지정할 수 있고, 같은 옵션을 중복 지정해도
무시됩니다. 키 옵션을 하나도 지정하지 않으면 `--right-cmd`가 기본값으로
적용됩니다.

## 설치 후 설정 (필수)

스크립트는 키 리매핑까지만 합니다. **시스템 설정에서 아래를 직접 지정해야**
실제로 한/영 전환이 동작합니다. 설치가 끝나면 같은 내용이 터미널에도 안내됩니다.

1. **F18을 전환 키로 등록 (필수)** — 시스템 설정 > 키보드 > 키보드 단축키... >
   입력 소스에서 `이전 입력 소스 선택`을 더블클릭하고 리매핑한 키를 누릅니다.
   (체크박스가 꺼져 있다면 함께 켜주세요.) 여러 키를 지정했다면 아무 키나
   하나만 눌러 등록하면 됩니다.
2. **Caps Lock 한/영 전환 끄기 (권장)** — 시스템 설정 > 키보드 > 텍스트 입력 >
   입력 소스 옆 `[편집...]`에서 `Caps Lock 키로 ABC 입력 소스 전환`을 끕니다.
   (영문 표기: `Use Caps Lock key to switch to and from ABC`.) macOS 12
   이하에서는 시스템 환경설정 > 키보드 > 입력 소스 탭에 같은 항목이 있습니다.
   전환 키가 두 개면 현재 입력 상태를 착각하기 쉬우므로 함께 정리하는 걸
   권합니다.
3. **Caps Lock 키를 완전히 죽이기 (선택)** — 2번만 꺼도 한/영 전환은 안 되지만
   대문자 고정 기능은 남습니다. 아예 쓰지 않으려면 시스템 설정 > 키보드 >
   키보드 단축키... > 보조 키에서 `Caps Lock 키`를 `동작 없음`으로 바꿔주세요.
   이 설정은 키보드별로 따로 저장되므로, 창 위쪽 `적용 대상`에서 사용 중인
   키보드를 각각 선택해 설정해야 합니다.

## 제대로 적용됐는지 확인

```sh
hidutil property --get "UserKeyMapping"
```

리매핑이 적용됐다면 아래처럼 `HIDKeyboardModifierMappingSrc` /
`HIDKeyboardModifierMappingDst` 값이 출력됩니다. **출력은 16진수가 아니라
10진수임에 주의하세요.**

```
(
        {
        HIDKeyboardModifierMappingDst = 30064771181;
        HIDKeyboardModifierMappingSrc = 30064771303;
    }
)
```

아래 표로 10진수 값이 어떤 키에 해당하는지 확인할 수 있습니다.

| 키 | 16진수 | 10진수 |
|---|---|---|
| 오른쪽 Alt(Option) | `0x7000000E6` | 30064771302 |
| 오른쪽 커맨드 / 오른쪽 Win | `0x7000000E7` | 30064771303 |
| 한/영 키 (LANG1) | `0x700000090` | 30064771216 |
| F18 (매핑 대상) | `0x70000006D` | 30064771181 |

위 예시는 오른쪽 커맨드(`30064771303`)가 F18(`30064771181`)로 매핑된
상태입니다.

LaunchDaemon이 제대로 등록됐는지는 아래 명령으로 확인할 수 있습니다.

```sh
sudo launchctl print system/local.hangeul-keymap
```

## 문제 해결

- **키를 눌러도 한/영이 안 바뀐다** — [설치 후 설정](#설치-후-설정-필수) 1번을
  안 한 경우가 대부분입니다. 리매핑은 키를 F18로 바꿔줄 뿐, 단축키 등록은
  사람이 직접 해야 합니다.
- **시스템 설정 단축키 칸에 아무것도 안 잡힌다** — 리매핑이 적용되지 않은
  것입니다. 위 [제대로 적용됐는지 확인](#제대로-적용됐는지-확인)으로 확인하고,
  안 잡혀 있으면 `install`을 다시 실행하세요.
- **내 키보드의 한/영 키가 LANG1인지 오른쪽 Alt인지 모르겠다** —
  `--right-alt --hangul-key`를 함께 지정하면 어느 쪽이든 동작합니다. 실제로
  보내는 쪽만 매핑되고 나머지는 아무 영향이 없습니다.
- **`--device`로 설치했는데 안 먹는다** — 목록에서 고른 VendorID/ProductID가
  실제 사용 중인 키보드가 맞는지 `list`로 다시 확인하세요. 무선 키보드는
  리시버(동글) 쪽 ID로 잡히기도 합니다.

## 제거

```sh
sudo ./hangeul-keymap-setup.sh uninstall
```

LaunchDaemon을 내리고 plist를 지운 뒤 현재 세션의 리매핑까지 해제합니다.
이전 버전(`local.keymap`)으로 설치했던 plist가 남아 있다면 그것도 함께
정리합니다.

설치할 때 사람이 직접 바꾼 시스템 설정(F18 단축키, Caps Lock 관련 설정 두
가지)은 스크립트가 건드릴 수 없으므로, 제거 후 출력되는 안내를 보고
되돌려주세요.

특히 F18 단축키를 그대로 둔 채 Caps Lock 전환도 꺼져 있으면 **한/영 전환
수단이 하나도 남지 않을 수 있습니다.** 둘 중 하나는 꼭 되살려주세요.

## 동작 방식

`/Library/LaunchDaemons/local.hangeul-keymap.plist`를 만들어, 부팅 시
아래와 같은 명령이 실행되도록 등록합니다. 지정한 키가 여러 개면 그만큼
엔트리가 늘어납니다. 예를 들어 `--right-alt --hangul-key`로 설치하면:

```
hidutil property --set '{"UserKeyMapping":[
  {"HIDKeyboardModifierMappingSrc":0x7000000E6,
   "HIDKeyboardModifierMappingDst":0x70000006D},
  {"HIDKeyboardModifierMappingSrc":0x700000090,
   "HIDKeyboardModifierMappingDst":0x70000006D}]}'
```

`--device`로 설치하면 같은 딕셔너리에 `"HIDMatch":{"VendorID":...,
"ProductID":...}`가 추가되어, 지정한 키보드 한 대에만 리매핑이 적용됩니다.

사용된 HID 코드는 아래와 같습니다. 좌/우 키는 서로 다른 값을 가집니다.

| 키 | 코드 |
|---|---|
| 오른쪽 Alt(Option) | `0x7000000E6` |
| 오른쪽 커맨드 / 오른쪽 Win | `0x7000000E7` |
| 한/영 키 (LANG1) | `0x700000090` |
| F18 (매핑 대상) | `0x70000006D` |

이 외에 시스템 파일을 수정하거나 백그라운드에 상주하는 프로세스는 없습니다.

## 알려진 제한

- 블루투스 키보드를 껐다 켜거나 새 키보드를 연결한 뒤 리매핑이 풀렸다는
  보고가 있습니다. 이 경우 재부팅하거나 `install`을 다시 실행하면 됩니다.
- `--device` 모드로 설치한 경우, `uninstall`의 즉시 해제가 적용되지 않을 수
  있습니다. 재부팅하면 확실히 초기화됩니다.
- 리매핑한 키의 본래 기능은 사용할 수 없게 됩니다. 오른쪽 Alt를 쓰는 경우
  Option 조합 특수문자(`®`, `≠`, `…` 등)를 오른쪽 키로는 입력할 수 없습니다.
  왼쪽 키는 그대로 남아 있어 실사용에 큰 지장은 없습니다.
- 시스템 설정 > 보조 키에서 Command/Option을 서로 바꿔 놓았더라도, hidutil은
  그보다 낮은 계층에서 동작하므로 매핑 대상은 **물리적인 키 위치** 기준입니다.
- 리매핑 대상이 늘어날수록 원래 기능을 잃는 키도 늘어납니다. 필요한 키만
  고르는 편이 낫고, 특히 오른쪽 커맨드는 맥에서 자주 쓰이므로 윈도우용
  키보드가 아니라면 굳이 여러 개를 걸 이유가 없습니다.
